# RayAI 网页 UI 设计规则

移动端像成熟的创作 App，桌面端像高效的生图工作台。让提示词、参考图和生成结果成为主角。动效用来解释状态与反馈，不用来装饰界面。

下文的尺寸、时长和色阶是建议默认值；若调整，需说明场景，并以可读性、可操作性和一致性为准。功能、无障碍和用户的系统偏好优先于视觉规则。

## 1. 配色、对比与层级

- 使用低饱和中性色。相邻大面积表面可用约 1%–3% 的微色阶差分层，但不把微色阶当作控件边界或焦点的唯一提示。主操作用明暗对比突出；错误、警告、成功保留语义色，配合文字或图标，不只靠颜色。
- 不用装饰性渐变、发光、粗边框、表情符号、装饰徽章或营销式感叹号。图标统一为一套线性图标，统一笔画、视觉尺寸和对齐方式。用户图片和生成内容不受界面配色规则限制。
- 用留白和微色阶区分常驻模块；菜单、弹窗等浮层可用两层柔和阴影：近层定义边缘，远层提供层次。输入框可用低对比内外双环阴影，不用高亮轮廓作常态装饰。焦点必须清晰可见；阴影不足时保留必要的细边或焦点环。
- 对现有或新增主题分别校验。深色优先用表面明度分层，不照搬浅色阴影；浅色文字可适度降低字重，不牺牲可读性。以 WCAG 2.2 AA 为基线，普通正文对比度至少 4.5:1，适用的控件边界和状态指示至少 3:1。

## 2. 排版、尺寸与对齐

- 建议共用间距档位 `4 / 8 / 12 / 16 / 24 / 32 px`、圆角档位 `8 / 12 / 16 / 24 px`。组内紧凑，组间留白；同类元素共享左边线，同级面板共享圆角，不靠逐个偏移对齐。
- 等距嵌套时，**外圆角 = 内圆角 + 内边距**，对应圆心对齐。例如内角 `12 px`、间距 `8 px`，外角由计算得到 `20 px`，不另造通用档位。
- 进度、计数、尺寸、缩放百分比使用 `font-variant-numeric: tabular-nums`，并验证所用字体支持等宽数字。为 `9% → 100%` 等位数变化预留宽度，正文不改用等宽字体。
- 短标题优先用 `text-wrap: balance`，窄屏检查中文孤字和英文孤词；不用固定换行修单个宽度。长正文自然换行。
- 图标尺寸不压过文字，图文间距一致。移动端常用操作建议至少 `44 × 44 CSS px`；桌面同样保留足够的点击区与清晰的键盘焦点。

## 3. 按场景组织界面

- **设置**：默认设置名和说明在左、控件在右，同类控件对齐；去掉无用套框，用标题和留白区分分组。窄屏若左右排影响阅读或操作，允许上下排列。
- **登录、注册、模型配置等录入表单**：标签在上、输入框在下，说明和错误贴近对应字段，不强制套用设置页的左右布局。
- **侧栏**：局部优化默认保留内容、顺序、配色与交互。统一两侧留白、字号、圆角、行高、图标和图文间距，组间比组内更松；标题可截断，但不能挤掉操作位。所支持的重命名、置顶和删除不应只能靠悬停发现。
- **聊天与生图**：提示词、参考图、画面设置与发送优先可用。手机单独验证安全区、软键盘和滚动；桌面单独验证阅读宽度、长对话与键盘操作。

## 4. 交互与动效

| 场景 | 规则 |
| --- | --- |
| 状态切换 | 优先 `transition` 或能从当前进度继续的等效方案；快速反向时不能先播完再反转。常规反馈建议 `100–180 ms`，面板过渡 `180–280 ms`。不用匀速驱动位置或尺寸，不用需要重播的关键帧承载开关、选中等交互状态。 |
| 入场 | 短距位移＋淡入，起步快、收尾轻。只给首次出现的主要模块错峰，建议 `25–50 ms`；不延迟操作，不在切换历史对话时重播整屏。 |
| 退场 | 小幅位移＋淡出，可加少量模糊。不让普通菜单、面板或提示飞出屏幕；关闭后不拦截点击或留在键盘焦点顺序中。 |
| 图标切换 | 固定占位内做交叉淡化、小幅缩放和轻微模糊；点击区不动，无障碍名称随状态更新。 |
| 侧栏高亮 | 组内短距滑动，跨组淡出／淡入。若用 View Transitions，按组隔离 `view-transition-name`，同一快照内名称不能冲突；不支持时回退到 CSS 淡化或直接切换，导航仍能使用。没有分组时不为动效硬造分组。 |
| 展开／收起 | 优先 Grid 或等效的连续布局过渡，支持反向打断；收起的内容不能继续获得焦点。 |
| 流式文字 | 仅在确有流式文本时使用。可对字词或短片段轻微淡入、模糊、错峰，不做装饰性渐变，不为等待动效延迟文字可读性。 |
| 拖拽及反馈 | 拖拽跟手，释放不做装饰性回弹。点赞等低风险正反馈若存在，可做一次小幅弹性反馈，不扩散到普通按钮。轻量成功提示约 `2.5 s` 后消失；错误、待处理或带操作的提示不强制按时消失。 |

尊重 `prefers-reduced-motion`：取消非必要位移、模糊、错峰、弹性和循环装饰，必要时只保留短淡化或直接切换。生成、连接等状态仍须有清楚、可访问的文本反馈。

## 5. 修改边界与验收

- 局部 UI 任务不改变邀请码流程、会话持久化、模型选择、画面参数和生图请求语义。现有极光、光晕等旧效果，在改到对应模块时替换，不借局部任务重做全站。
- 分开验收窄屏、常见手机宽度和桌面；检查已支持的主题、长中文标题与模型名、键盘焦点、减少动态效果、移动软键盘与安全区。未做真机或实测的部分不要标为通过。
- 连续开关面板、快速切侧栏项目、动画中途反向，确认没有闪回、错位、残影、焦点丢失或按钮失灵。
- 回归提示词输入、参考图添加与移除、生成中/成功/失败状态和图片查看。不为新动效引入与本次改动无关的功能或依赖。
